# rhTV 网页桥接完整方案

核查日期：2026-10-01。目标：[用户提供的 rhTV 页面](https://rhtv.runninghub.ai/projects?model=476)。

本文是调研与开发方案，不是已上线功能。本次只检查公开页面、界面控件、文档和本地代码；没有使用用户账号登录，没有上传素材，没有提交生成或测试扣费。附件中的文字仅作证据，不作为操作指令。

后续实施更新：V1.0.3 已增加自动化代码，默认关闭并标为实站联调待验收。本文保留原始设计；具体实现、差异和验证范围见同目录 `rhtv-web-bridge-implementation-2026-10-01.md`，不要把方案内容当作实测结果。

## 1. 结论与前置条件

建议沿用 B 方案：在软件内部提供本机 API，由一个独立浏览器会话执行 rhTV 网页流程。它是“浏览器自动化桥接”，不是把网页地址填入 API 地址，也不是用普通反向代理就能转换接口。

- 使用入口：现有“视频 API”中新建连接，增加协议“rhTV 网页桥接（本机）”。不覆盖 MiniMax、通用 API、ComfyUI 或 RunningHub 云端工作流。
- 日常体验目标：在软件选图、填提示词、点击生成；软件管理网页、排队、取回结果。首次登录、会话失效、验证码、费用不确定时需要用户进入网页处理。
- 运行条件：电脑开机、联网，软件和受控浏览器进程仍运行。不承诺完全无浏览器、关机继续调度、永久免登录或永远免费。
- 技术判断：有同类开源实现可参考，但本次没有验证“此账号 + 此活动 + 此模型”的完整生成闭环，不能把可行性推断写成已打通。

**自动提交须先确认平台允许。** RunningHub 公开付费协议在 II.1.2“获取服务”部分限制通过自动化程序、脚本等获取服务，III.6 也限制未经授权的活动参与方式。条款对本次 rhTV 会员活动的具体适用应向平台确认；“自己账号、低并发”并不能证明获得授权。这是平台条款风险提示，不是法律结论。[官方付费协议](https://www.runninghub.ai/defray-protocol)

未确认允许时，先做本地素材整理、提示词准备、人工网页提交和结果导入；或选择官方 API。不要把半自动操作理解成规避条款的保证。本方案不含绕过验证码、伪装身份、修改计费、多账号领取优惠或向他人出售会员权益。

## 4. 软件入口与使用流程

### 4.1 视频 API 中新增什么

建议连接名为“rhTV H3 网页”，协议为 `rhtv_web`，显示名称为“rhTV 网页桥接（本机）”。继续使用现有 `api` 后端与连接列表，不必增加第四个顶层生成方式。

| 设置项 | 设计 |
| --- | --- |
| 本地服务 | 软件自动启动、停止并检测健康；实际端口由进程管理器确定 |
| API 地址 | 自动生成本机地址，不要求用户填写 rhTV 网页 URL 作为接口 |
| 认证 | 自动生成本机桥接令牌，与 RunningHub API Key、网页登录凭据区分 |
| 网页账户 | 登录、查看网页、重新检查状态；登录失效显示明确状态 |
| 模型 | 首期固定 Enhanced 的已验证适配项，显示真实网页选择结果 |
| 生成模式 | 文生视频、首帧、首尾帧、全能参考 |
| 参数 | 软件提交明确的时长、分辨率、比例，网页回读一致才继续 |
| 费用策略 | 默认且首期仅支持“只允许确认免费”；不支持自动切换付费 |
| 并发 | 单账户串行；不继承其他 API 的高并发配置 |
| 测试连接 | 仅检查本地服务、浏览器和会话，不生成视频、不消耗额度 |

这是拟开发的设置，不是现在填入某个端口就已经能用。普通 JSON 模板可做技术原型，正式版不能让用户自行拼接登录、引用和状态协议。

### 4.2 用户实际怎么用

1. 在视频 API 新建 rhTV 连接，启动桥接并在独立浏览器里手动登录。
2. 软件显示账号状态、模型与当前可验证的活动状态；未知状态保持未知。
3. 在现有分镜/视频面板选择参考图与模式，填写提示词和参数。
4. 软件冻结本次输入并入队，检查费用和附件绑定，通过后执行网页提交。
5. 任务区显示本地排队、等待处理、网页排队、生成、下载和完成等真实状态。
6. 完成的视频自动进入现有项目素材库并关联原分镜；异常可查看原网页。

平时不需要用户逐条打开网页操作，但网页进程仍然存在。首期采用有界面的受控浏览器，正常时可放在后台；无头模式、最小化和锁屏可用性需要实测，不作交付前承诺。浏览器退出后可以重连原任务，不能因此再次生成。

## 5. 参考图完整链路

### 5.1 模式与素材规则

| 模式 | 首期允许的图片输入 | 行为 |
| --- | --- | --- |
| 文生视频 | 0 张 | 不静默丢弃用户已选图片，存在图片时要求调整模式 |
| 首帧 | 明确标为首帧的 1 张 | 上传至首帧位置 |
| 首尾帧 | 明确标为首帧、尾帧的各 1 张 | 各自上传到正确位置，不以完成先后决定用途 |
| 全能参考 | 1-9 张图片 | 保留人物、场景、道具等语义信息并验证实际附件映射 |

“两张人物参考图”不等于“首帧加尾帧”。角色用途与网页附件位置是两套信息；网页不一定有“人物/场景”专用字段，不能假设发送一个 role 字段就会生效。提示词和已验证的附件引用共同表达用途。

### 5.2 传递的是文件和绑定清单，不只是 URL

当前代码已经有稳定槽位、人物 ID 和冻结素材机制，必须继续使用：

- 冻结原图字节及校验值，不传缩略图、预览地址或只在渲染进程有效的 blob URL。
- 每张图保留 `assetId`、`checksum`、原 `slotIndex`、`role`、`characterIds`；合照可对应多个人物，明确的空人物列表不能被猜测填充。
- 上传到本机桥接后只传不透明 `upload_id`。桥接用暂存文件完成正常网页上传，不向 rhTV 发送本机 HTTP 地址让云端抓取。
- 一张张确认上传完成、缩略图/附件记录已出现，再记录网页真实位置、可观察附件标识及引用形式；不能把文件选择成功当成上传成功。
- 提交前核对已选数量、文件与网页附件的对应、首尾帧位置、提示词引用、模型及参数。实际缺图或映射不明时不自动提交。
- 文件尺寸、大小、类型限制在适配验证中确认；超限明确报错，不暗中裁图、压缩或删除多余图片。确需转换时保留原件并展示变更。

### 5.3 槽位不连续、人物绑定与提示词

示例：本地槽 1 是人物甲，槽 2 已清空，槽 3 是人物乙；网页可能只显示连续的附件 1、2。此时保留“本地槽 3 -> 人物乙素材 -> 网页附件 2”的映射，不能修改用户原槽位，也不能继续错误引用不存在的网页附件 3。

H3 稿中的原图片编号以已有 `sourcePictures` 和人物绑定为依据，不必然等于当前槽号。应从可信来源重建本次传输引用，仅对可证明的引用位置进行确定性替换；不使用 AI 重写全文，不按文件名或脸部猜人，不改变对白、声音标签、镜头时序和其他正文。

如果网页使用 @附件、节点连接或结构化引用，需要通过网页真实控件建立绑定。本次尚未验证 rhTV 是否直接解释 `<Picture N>`，不能把粘贴这串文字等同于完成多图引用。界面应提供“原素材/原槽号/网页位置”的核对信息。

现有 `h3ReferenceWarnings` 是提示性质，继续保持，不把历史任务或其他协议改成强制人物审核。区分“稿件语义提醒”和“无法证明实际附件正确上传/引用”两种情况；后者才阻止 rhTV 自动提交或转人工处理。

### 5.4 批量与上一段尾帧

每条任务拥有独立冻结清单，不复用上一条网页草稿的附件。只操作桥接自己的草稿/专用项目，不清理或覆盖用户其他项目。素材留存在网页的生命周期需单独说明，不能声称关闭本地软件便删除了云端素材。

沿用现有上一段尾帧依赖：等前一条结果下载、校验和提取尾帧成功，才解析下一条预留输入；保留固定任务依赖，不能使用“最近生成视频”或“最新一张图”。自动尾帧与用户手选首帧冲突时明确处理，不静默覆盖。

首期不提供参考音频和参考视频自动上传。网页音频提示已看到，但当前视频输入链主要围绕图片；音视频需独立补齐素材类型、时长、大小、引用与隐私校验后再开放。

## 6. 本机架构与拟定接口

```text
现有视频面板 / 分镜批量队列
  -> 专用 rhTV 适配器：冻结输入、校验模式、携带稳定 clientId
  -> Electron 主进程管理的本机桥接服务
  -> Playwright + 独立浏览器配置目录
  -> rhTV 网页：上传、参数回读、费用检查、提交、跟踪
  -> 本地结果缓存与视频校验
  -> 现有下载入库、预览、分镜关联、尾帧链
```

复用 Node/Electron，浏览器工作放入受管子进程，避免阻塞界面。采用独立持久化浏览器目录，不占用或复制用户日常 Edge/Chrome 配置。浏览器目录按当前用户权限保护，不宣称全部文件都自动加密；本机令牌使用现有安全凭据存储，Cookie 不进入项目 JSON 或日志。[Playwright 持久化上下文说明](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-persistent-context)

以下均为新桥接的协议草案，不是 RunningHub 官方端点。基址为 `http://127.0.0.1:{实际端口}`，所有请求都必须认证：

| 方法与路径 | 含义 |
| --- | --- |
| GET `/v1/health` | 进程与协议版本；无生成副作用 |
| GET `/v1/session` | 脱敏登录状态和需要用户处理的原因 |
| GET `/v1/capabilities` | 本地适配能力、网页可观察参数、验证时间；未知不当作支持 |
| POST `/v1/assets` | 文件表单上传至本机，返回 `upload_id`、校验值和素材元数据 |
| POST `/v1/videos` | 持久化接收任务后立即返回桥接 `id`，不等待视频生成 |
| GET `/v1/videos/{id}` | 原任务状态、网页任务关联、等待原因、最终本地结果地址 |
| GET `/v1/videos/by-client/{clientId}` | 恢复提交响应丢失的本地任务，避免重复 POST |
| POST `/v1/videos/{id}/cancel` | 区分取消本地待提交任务、请求网页取消、仅停止本地跟踪 |
| GET `/v1/videos/{id}/content` | 只返回已校验且属于该任务的最终视频，支持现有下载入库 |

网页登录窗口的展示、桥接启动和关闭使用可信 Electron IPC，不提供可被任意网页调用的无认证管理接口。

请求内容包括：`protocol_version`、稳定 `client_id`、`model_key`、`mode`、`prompt`、`parameters`、`references` 和 `cost_policy`。`references` 只使用一份清单，条目含 `upload_id`、`asset_id`、`checksum`、`slot_index`、`role`、`character_ids`，以及必要的可信提示词引用锚点；不在 images、references、first_image 中重复携带整份 base64。

`model_key` 是桥接自有别名，不假装是网页 476 或官方 API ID。人物内部 ID 留在本机映射层，网页只接收生成所需的实际图片和提示词。`Idempotency-Key` 与稳定 `client_id` 对应；同键同内容返回原任务，同键不同内容返回冲突，不重新生成。

当前通用图片上传要求返回 HTTP(S) 地址，当前 `{{references}}` 模板也没有携带全部人物和素材身份信息，因此必须新增专用分支，不能仅保存一个 JSON 模板。旧协议保持原行为。

## 7. 状态、幂等与恢复

桥接必须分清三种 ID：软件 `clientId`、本机 `bridgeJobId`、网页 `upstreamTaskId/projectId`。本机接单成功不代表 rhTV 已经接单。

状态链：接单并持久化 -> 等待/准备 -> 上传并验证 -> 记录网页提交边界 -> 点击提交 -> 确认网页任务 -> 网页排队/生成 -> 下载验证 -> 完成。

- 网页点击前写入持久日志；日志包含冻结输入、账户绑定、参数、附件映射、适配版本和提交阶段。采用单写者与原子写入，不额外引入非必要数据库。
- 点击后超时、崩溃、失去任务 ID，均进入 `submission-unknown`。先查询原任务、核对专用项目证据，无法确定就交用户处理，不自动再次点击。
- 不能仅按相似提示词或最新缩略图关联结果。拿不到可靠网页任务身份是自动化交付的阻断项。
- 仅本地接单响应丢失时，用 `clientId` 查询桥接日志恢复。重启端口或本机令牌变化不能导致重新提交。
- 现有生成阶段尽量复用；新增专用等待原因，例如登录、验证码、免费窗口、费用不明、界面变化。等待和断线不是远程失败，也不能释放已提交/未知任务的占位。
- 当前按 API origin 分组的并发不能直接照搬：rhTV 以稳定的桥接账户范围串行，别名、端口变化、多个连接或项目不能绕过限制。浏览器目录加互斥锁，账号切换时暂停旧账号任务。
- 全局并发即使设为 100，rhTV 仍最多一个活动/提交不明任务。其他 API 继续原有并发规则。
- 本地待提交任务可明确取消；已提交网页任务只有观察到上游取消确认才显示“已取消”。关闭页面、停止查询或关闭软件不等于取消云端生成。
- 网页已成功但下载失败，只重试下载；链接过期时重新打开同一网页任务取结果，不重新生成。重试上传也应先核实当前草稿，避免重复附件。

没有网页侧幂等能力时，无法数学保证 exactly-once。这里的目标是“可确认的本地请求去重 + 不确定时不自动重发”，而不是宣称绝不会发生上游重复任务。

## 8. 费用与隐私保护

### 8.1 只免费提交的检查

每次准备提交，都核对当前账号、会员/活动资格、选中模型、模式、时长、分辨率和网页对本次任务显示的费用。模型菜单写着免费，不等于这一次配置免费。

“21:00-10:00”仅作为观察到的提示；需确认网页所说当地时间对应的实际规则。不得仅看电脑时钟决定提交，不修改时区争取权益，不把活动时间写成永远有效的常量。临近边界应留出待实测确定的余量，每个任务重新检查。

费用不明、免费资格不明、额度不足、限制弹窗或付费确认出现时暂停，不默认通过，不自动切换官方付费 API。用户希望排队等免费窗口时，仅在软件运行且条件重新确认后继续。

**本地费用检查不是平台级零扣费保证。** 如果网页没有“只接受零费用”的原子保护，价格可能在检查与提交间变化；严格要求绝不扣费时，不能承诺无人值守自动提交，应保留人工确认或放弃该通道。首次实测需核对任务计费记录，不能仅根据余额变化推断。

### 8.2 本机服务边界

- 只监听 `127.0.0.1`；即使在本机也要求随机强令牌，拒绝任意 CORS 来源和异常 Host，防止第三方网页触发任务。
- 对软件自己的桥接地址做窄范围放行，不为此全局关闭私网、重定向、下载与路径校验。服务重启后的地址/令牌通过可信 IPC 更新；历史任务仍按固定桥接身份恢复。
- 上传只接受允许的文件类型和大小，校验内容，不允许客户端传任意磁盘路径或任意远程 URL 让服务读取；临时文件只能位于受管目录。
- 网页所需账号登录由用户完成。验证码、二次验证和风控中断交用户处理，不使用第三方解码、Cookie 共享或绕过机制。
- 不公开浏览器调试端口，不把站点 Cookie 或认证头带到任意下载重定向地址。优先使用浏览器正常下载和可验证结果来源。
- 日志默认只存脱敏状态、错误码、任务关系；敏感截图和网络追踪仅在用户明确开启诊断时保留，设置保留期限。
- 本地暂存文件在任务结束后按策略清理，冻结原图和结果按项目资产规则保留；网页已上传素材需按平台自身规则管理。

## 10. 验收与推进顺序

### 10.1 免费的本地验证

用本地模拟站点/固定页面测试，不调用真实生成：

1. 四种模式、0/1/2/9/10 张图片的校验，缺文件、类型不符、上传失败。
2. 槽位空洞、图片重排、同名文件、同图多用途、合照多人物和空人物绑定。
3. 提示词引用映射及对白/声音/时序不变，未知语义提醒不影响其他协议。
4. 登录过期、验证码、账号切换、活动结束、价格未知、模式参数被网页自动重置。
5. 重复 clientId、同键异内容、点击前后崩溃、响应丢失、重启变端口、人工网页同时操作。
6. 多项目/多连接/全局并发下的 rhTV 串行，未知任务不放行后续生成。
7. 取消未提交任务、取消未确认任务、只停止跟踪的区别。
8. 下载过期、断线、错误文件、磁盘空间不足，结果正确关联及尾帧链恢复。
9. 未授权本机请求、跨站调用、任意文件读取、过量上传、错误下载来源。
10. 干净 Windows 便携包、中文和空格路径、无开发环境、浏览器更新后的冒烟测试。

### 10.2 真实网页验证关卡

在平台允许、用户明确授权素材上传和真实提交后进行。先核对免费资格和计费机制，再至少验证文生一条、两张有明确对应关系的全能参考一条；首帧、首尾帧各单独验收后才开放。测试使用可辨识且已获授权的素材。

验收不能只看“按钮点了”：必须确认参数与图片绑定正确、网页任务身份可恢复、费用记录符合预期、视频能下载入库、重启不重复提交、异常可人工接管。生成模型本身可能不完全遵循人物或内容要求，应与素材传输正确性分开评价。

若取不到可靠费用信息、网页任务身份或附件引用关系，停止无人值守模式，将该能力标为未通过，不能用猜测补足。网站更新导致关键定位失效时也停用自动提交，更新适配并回归测试后再开启。
