# 莲华视频导演台 4.7.1 发布说明

发布日期：2026-11-16（亚洲/上海）。

## 版本定位

修复本地 ComfyUI 视频的时长识别遗漏与未选参考图仍尝试加载默认文件的问题。按十进位规则从 4.7.0 升为 4.7.1，同版提供 Windows EXE 和正式签名 Android APK。

## 视频时长

- 导入工作流时，沿明确的秒数输入和 H3 换算连线识别时长入口，避免工作流已有秒数控件但生成页仍显示“请先绑定节点”。
- 已有工作流缺少 `duration` 映射时，界面与请求复用能够明确识别的时长来源；已有手工映射优先保留。
- 用户提供的 H3 工作流实际控制链为“秒数控件 → 秒转帧公式 → H3 length”。时长写入原秒数控件，保留工作流已有公式及帧数对齐，不再换算一次。
- 不按节点编号、默认值或标题猜测参数语义。未知公式和存在冲突的候选继续通过现有参数管理入口配置。

## 少量参考图

- 本次请求按实际选择处理 H3 的可选参考图输入，未选映射槽不再继续读取原作者的文件名或 `None`。
- 已选图片沿实际 H3 消费顺序发送，Picture 编号与实际请求图片列表保持一致；不重复图片填满槽位。
- 仅处理已经明确关联到 H3 可选参考图的未选分支。仍用于首尾帧、蒙版或其他有效消费者的图片节点保留。
- 单段、长剧情批量和自定义生视频复用相同处理；保存的工作流原件、已有提示词与历史任务冻结快照不自动改写。
- 同一附件另有三路 `None` 参考音频。请求省略明确接入 H3 可选参考音频的空占位，避免图片修复后仍把 `None` 当音频文件读取；非空固定音频和仍有其他消费者的加载器保留。
- 新任务记录本次选图语义；旧排队或复用任务按原快照保留默认图片和编号，避免升级后改变已冻结的请求。

没有新增运行时校验、内容审核、生成拦截、自动重试、模型请求或按钮，没有进行哈希测试。

## 验证状态

本版一次集中执行的五个定向脚本全部通过：秒数来源识别和既有映射优先、15组可选图片及空音频处理、真实任务引擎的模拟上传与提交、8组H3图片顺序、视频画布导入。任务引擎用模拟请求覆盖新任务与旧排队任务，没有发出真实API请求。记录：`output/diagnostics/comfy-video-4.7.1/focused-checks.json`。

共享类型检查、Vite生产构建、Windows便携包及Android正式release APK构建完成。打包首次类型检查发现一处类型收窄写法问题，修正后通过；没有在打包前另跑全量类型检查。构建保留既有分包循环依赖和大chunk提示。

实际便携EXE用隔离数据启动，显示v4.7.1，进入视频导演台并正常退出，页面和运行时错误为0。APK的versionName=4.7.1、versionCode=471，签名验证通过，正式证书与4.7.0一致；包内有生产index.html及30个直接生产JS文件，没有签名私钥或配置。

制品大小：EXE为229,291,069字节，APK为11,790,811字节。证据：`output/diagnostics/comfy-video-4.7.1/artifacts.json`、`output/playwright/packaged-startup-4.7.1-vVj70u/report.json`、`release/Android-4.7.1-签名验证.txt`。

未连接客户实际 ComfyUI 生成视频，未执行 Android 真机安装或覆盖升级验收；本地请求检查、构建和签名检查不等同于实际生成或真机验收。

## 交付

- Windows x64：`lianhua-video-director-4.7.1-windows-x64-portable.exe`。
- Android：`lianhua-video-director-4.7.1-android.apk`，沿用既有正式发布签名，最低 Android 8.0 / API 26。
- GitHub 同版提供 EXE、APK、更新说明、恢复源码 ZIP、安卓安装说明、能力与验证记录和 Windows 启动器，共 7 个附件；本地既有 SHA-256 清单不上传为 GitHub 附件。签名私钥和口令保存在仓库外。
- 4.7.0 及更早交付文件保留原版本号与文件，不覆盖、不重编号、不删除。

构建：`npm run pack:all`；交付：`npm run deliver:4.7.1`。打包流程执行一次共享类型检查和生产构建，两端复用同一次结果。
