# 莲华视频导演台 2.2.9

发布日期：2026-10-15。

## 特价图片参考的首中尾用途

使用“特价 2.5”等经典图片参考模型时，设置首帧、中间帧或尾帧用途原先会被软件误当成原生首尾模式，出现“不支持”提示并禁止提交。本版精确修复特价 2.0、特价 2.5 的这类本地误拦。

图片继续按原有 `images` 顺序发送，本次 `prompt` 保持原有提交内容，不因首帧、中间帧或尾帧用途禁止请求，也不额外添加 `mode`、`first_frame` 等原生帧字段。首中尾用途表达本次图片的参考职责，服务仍按经典图片参考协议处理。

本轮依据 2026-10-15 查阅的[老李视频 API 对接文档](https://video.laoliimage2.win/docs/video-api/)：经典 `images` 使用原始 Base64 或 Data URL 并保持顺序。当前模型图片容量由下面的只读读取流程取得，不在本地按模型名填写固定数量。

## 从当前接口读取图片容量

打开单段或批量选图弹窗时，软件只读请求当前服务的模型信息 `GET /models` 及同源 OpenAPI，按当前接口和模型精确匹配图片容量。解析当前模型的 `images.maxItems`，或混合 `references` 中图片条件对应的 `maxContains`，不会把包含音频的素材总量当成图片容量。

选图弹窗按读取容量显示全部槽位，包括空槽。可先给空槽设定首帧、中间帧或尾帧用途，再补选图片；已有选图和本段用途保留。界面显示读取来源链接与读取时间，并提供手动重新读取按钮。

切换接口或模型后，容量只按当前配置匹配，不沿用其它模型的结果。服务未返回有效容量时明确显示未读取到，不按模型名称在本地补出固定数量。已有选图超过读取容量时仍可见，并提示超出容量，不截断图片。空槽用途记录保留；切换到容量较小的模型时，旧空槽用途不撑大当前槽数。

提交预检的图片数量限制也改用实际读取容量，移除按模型名固定图片数量的规则；容量未知时不猜上限，真实服务错误仍按原流程显示。

自定义请求模板不套用默认 schema 的图片容量。原任务保存的冻结资料继续保留。

## 接口与兼容

H3-KS、原生全参 2.5 等模型继续保留各自文档明确的原生帧限制。现有传图、查询与任务行为继续沿用，原稿、历史任务和 2.2.8 的多张中间帧设置保留。

参考用途不表示已验证原生帧硬控制。本轮未实测真实服务在指定时刻复现首帧、中间帧或尾帧的效果，具体生成结果由服务和模型决定。

没有数据迁移，不自动重新生成提示词或任务；保留已有项目、原稿和历史交付文件。版本按十进位规则从 2.2.8 递增至 2.2.9，2.2.8 及更早历史交付不覆盖、不删除。
