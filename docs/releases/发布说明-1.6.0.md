# 莲华视频导演台 1.6.0 发布说明

修复MiniMax H3视频实际选择6张图片，提示词仍引用Picture 7／8／9，导致RunningHub工作流返回805的问题。沿用1.5.9的普通、私密、分镜和首尾帧生图分辨率提醒及GPT 4K尺寸适配。

## 根因与修复

旧图片清单、可定位人物身份和本次实际选图是不同资料。旧流程把图片映射依赖于人物绑定与原稿精确匹配；一条旧引用缺少来源时会保留整份旧稿。RunningHub虽正确上传所选图片，却直接发送含旧编号的正文，没有核对正文中的引用是否实际连接。

新版按可证明的原资产ID同步图片编号，保留未知引用的明确说明；图片来源清单与人物身份锚点独立处理。兼容历史清单中的资产字段与标签格式，支持本次改选图及尾帧衔接。剧情、对白、镜头时刻和人物身份不随编号调整改写。

从失败任务选择新提示词、增加或直接移除当前图片会解除快照复用，让新选择实际生效；真正沿用旧任务的重试继续保留原快照。非冻结旧英文草稿缺失语言字段时，仅在原稿与翻译来源可证明的情况下补齐英文标记。

提交前根据明确输入映射检查未连接的图片引用，有问题时直接列出编号和实际选图情况，不再让可确认的损坏引用进入付费视频请求。不能证明的工作流内部图序不猜测；手写且与当前输入正确对应的H3仍可使用。未自动补图、重复上传凑数或关闭工作流校验。

## 使用方法

保存项目并退出旧版，保留整个“莲华视频导演台数据”文件夹，使用1.6.0打开。失败批次的历史记录与快照保留，不会自动重发。

有尾帧依赖的失败批次先停止原批次未提交项，再选择失败段与所需后续段，核对图片及用途后生成新批次。有原资产清单的旧编号会按本次选择同步。仅缺人物锚点时可用“修复人物图片绑定”；缺少原图来源、无法证明旧编号对应时，应从提示词导演台重新生成该段H3，不把旧编号强行绑定到另一人物。

## 验证范围

图片来源与绑定12组专项、原绑定27组、导演草稿专项、RunningHub图片协议20项及提交前校验专项通过。覆盖旧9号图片清单到当前6张、损坏人物锚点、英文历史草稿、引用别名、部分缺失来源、字面对白保护、手写正确H3与冻结重试；错误单段和批量请求在读取图片、上传、保存新任务及收费POST之前停止。

真实App与生成引擎的隔离界面验证通过：普通英文两段完成2个模拟提交和12次上传；英文尾帧衔接两段完成2个模拟提交、12次上传和1次本地抽帧。最终计数为6，Picture1–6逐项对应正确文件，第二段尾帧占第1槽；保存快照与最终请求相同，原中英文稿、旧9图清单与历史任务不变。直接移除冻结任务参考图后解除快照复用，保留原提示词、种子与剩余图槽。尾帧首轮因测试桥缺少本地媒体mock而失败，补齐后仅重跑该项通过。

TypeScript检查、前端生产构建与Windows便携包构建通过。生产冷启动首次检查发现新增解析器的分包初始化循环，将解析器与H3绑定合同放入同一分包后重新构建，启动专项通过：显示1.6.0，普通与私密新建分辨率仍为1K，浏览器无异常。打包内版本以及最终生产页面和H3合同文件与已验证产物一致。构建仍有既存循环分包和大文件提示。所有生成验证使用合成资料和本地模拟接口，不调用真实付费视频服务，未追加全量回归。

构建：`npm run pack:win`；交付：`npm run deliver:1.6.0`。按十进位版本规则由1.5.9进位至1.6.0，历史版本与交付文件保留。
