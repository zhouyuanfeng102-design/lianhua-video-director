# 莲华视频导演台 0.5.153 发布说明

发布日期：2026-09-24

## 版本定位

视频任务可选择排队或并发数量，修复普通批量只串行提交、却让多个远端视频同时运行的问题，并为视频任务显示具体失败原因与脱敏错误详情。同时修复私密档案无条件进入执行稿、普通衣着约束被删除导致无依据裸露的问题。

## 普通与私密五视图

- 新建入口中的普通四视图、私密四视图改为五视图。一张横向3:2画布，左侧约30%分上下两格：正面头肩特写、严格90度侧面头肩特写；右侧约70%为三个全高区域：正面全身、严格90度侧面全身、背面全身。
- 两个头像近景独立放大，仅三个全身统一尺度、相机高度与基线。保持同一人物/物种结构、普通或私密模式指定的状态与当前风格；不照搬版式示例的人物、服装或场景，不变成五个全身，不额外增加三分之四视角。
- 新类型为`five-view`与`private-five-view`，保存恢复、资产、任务、分类预设和重试均保留。单张五区域仍只调用一次图片生成；生图张数表示整张五视图的数量。
- 使用五视图专用布局负面约束，避免工厂单图规则中的“禁止多视图/禁止身体裁切”等把两个头像补成全身；普通模式保留用户明确填写的额外负面词。分类模板按本次布局安排头像和全身，只精确升级未修改的旧内置项，保留停用、删除及自定义内容。
- 旧`turnaround`/`private-turnaround`保留四视图历史含义，原图片、任务名、提示词与冻结规则不改；重试旧任务不会假标为五视图。需要新五视图请从新入口生成。
- 私密四合一、全身、特写、九宫格及既有安全限制不改。五视图要求交给既有AI转换流程，不新增本地图块语义审核；本轮不调用收费接口生成测试图片。

## 普通五视图分类预设

- 新增“GPT2.5 · 五视图精修”“K2 / Krea-2 · 五视图质感”“GPT2.5 · 微NSFW五视图”，均为普通角色设定图的自然语言分类；不混入私密五视图分类。
- 轻/微NSFW直接复用现有“GPT Image 2.5 微 NSFW · 角色参考图”的systemPrompt、outputRules和negativePrompt原文，原规则正文不改、不另造尺度或词库。版式由已选五视图合同决定；请求时仅移除与五区域/头像裁切相冲突的已知布局负面词，其余原有限制保留，原预设不改写。
- GPT普通预设的分区、主体身份和材质光照组织参考[OpenAI GPT Image 2.5 提示指南](https://developers.openai.com/api/docs/guides/image-prompting)；K2沿用项目已有Krea-2自然语言规则。没有改模型名、API根地址、图片尺寸、quality、seed或moderation，未用收费出图验证成图质量，也不保证所有模型每次精确生成布局。
- 新目录版本12只一次性添加新项和相应规则的可选项，既有分类默认绑定不重写。仅明确是新five-view、没有手选分类且相关工厂配置未编辑时推荐对应模型项；旧turnaround、其它OpenAI兼容模型和用户自定义不强推，微NSFW须显式选择相关规则/预设。
- 已保存的手选设置、停用、删除、重命名、自定义内容以及历史任务提示词/转换器快照均保留。

## 私密资料与衣着作用域

- 角色有私密档案不代表镜头需要展示；亲吻、拥抱、触碰和衣物外动作不构成脱衣指令。不再由宽泛私密标签删除人物服装，衣橱资料作为基准，当前剧情/已确认进入状态与明确变化优先。
- AI规划仅接收公共人物字段、角色ID及可用私密字段名称，不接收整份私密档案正文。AI在现有规划请求中按当前镜头明确可见需求选择必要字段；没有选择则只使用普通身份。程序只检查字段、角色ID和结构，不新增本地内容语义拒绝，也不额外发起独立资料选择收费请求。
- 已选择资料按镜头传给转换和中英文AI复核，只取对应角色/字段，不扩展到相邻镜头；已确认换装不会被旧衣橱反向覆盖。明确的剧情与镜头事实不被本地删改。
- 旧全局锁中的自动整份私密档案段只在请求/编译输入隔离，不重写已保存的档案和原文。受影响旧稿不再被标为当前合格结果；未受影响的公共H3稿保留兼容，无需全部重新生成。
- 派生分镜图片也遵守当前可见资料范围；首帧和自定义中间静帧不直接继承整镜未来才可见的私密资料。图像工作台中用户明确选择的私密资料制作与既有安全限制不变。
- 已有视频不会被自动修复或覆盖。要应用规则，请主动刷新有问题的当前段提示词，再确认是否重新生成视频；系统不会自动重跑收费任务。

## 视频执行方式

- 视频导演台与生成任务的视频页共用“排队生成 / 并发生成”设置并自动保存。默认排队，一次1个；并发模式可填写1–100的整数。无效输入不保存、不静默提高数量。
- 控制真实在途生成名额，远端排队、运行、提交结果未知均占位，不在拿到任务ID后立即放行。单条、普通批量、跨项目、尾帧链和继续任务不能各自绕过全应用上限。
- 调低数量不取消已发出的任务；已有运行数超过新限制时等待释放名额。调高后按新上限继续已授权的本地排队任务。服务商账号、工作流和外部其它任务的限额仍然有效，本设置不会增加服务商额度。
- 普通无依赖任务在前项明确结束后可以继续；尾帧任务仍必须等待准确前段成功、保存并选定成片。仅停止本地跟踪或查询失败不代表远端结束，不会借此放行重复生成。
- 未确认远端结束的记录及其项目保留，不能靠删除记录清空占位。重启从持久状态和提交断点恢复，不自动重跑历史失败项，也不重新提交已发任务。

## 视频失败原因

- `api queue limit reached, please retry later | API 并发数已达上线` 明确显示接口并发数量已达上限，不再替换成“暂时无法识别原因”，也不误判为账户余额或提示词错误。
- 主失败原因只显示一次。通过“查看错误详情 / 复制错误详情”查看HTTP、错误码、原始说明及节点失败原因；保存失败、按钮操作错误也保留可读详情。
- 未识别的节点说明放在技术详情，不覆盖已知主因。密钥、请求正文、提示词及图片数据继续脱敏，查看或复制不会调用生成接口。
