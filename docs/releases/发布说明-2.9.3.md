# 莲华视频导演台 2.9.3 发布说明

发布日期：2026-10-21（亚洲上海）。

## 本次修复

修复 2.9.2 中每次点击剧情分段仍会卡顿的问题。切段会保存当前选中位置，这只改变项目的界面状态；但此前显示缓存依赖整个项目包装对象，保存选中位置就会使缓存失效，再次计算所有分段的来源与衔接状态。

现在缓存依赖实际剧情、分镜、人物、地点、道具、参考素材以及章节归属。保存选中位置不会清空来源缓存，真实来源编辑和切换章节仍会重新计算。保留原有当前选段保存、自动保存、历史与生成任务行为，不新增运行时校验、内容审核、生成拦截、自动重试或模型请求。

## 定向验证

采用用户当前项目的隔离副本，对照 2.9.2 测量连续点击第 2、3、4、2、3 段。原项目文件只读，测试使用独立浏览器存储和默认关闭的 API，移除隔离副本中的后台任务，避免启动任务。每次点击后等待保存阶段，检查完整中文稿、缺失英文的显示状态、选段保存和重新载入恢复；测试报告只保存汇总计数和耗时，不输出正文。

| 点击分段 | 2.9.2 | 2.9.3 |
| --- | ---: | ---: |
| 第 2 段 | 1337 ms | 251 ms |
| 第 3 段 | 1329 ms | 235 ms |
| 第 4 段 | 1289 ms | 226 ms |
| 再点第 2 段 | 1308 ms | 118 ms |
| 再点第 3 段 | 1285 ms | 118 ms |

每次切段的完整显示缓存重建从 2 次降至 0 次；Seedance 来源构建从 48 次降至首次访问 4 次、再次访问 0 次。上述耗时来自带计数的开发模式隔离副本，实际使用耗时会随机器与项目变化。

定向验证通过：原中文稿逐字一致，英文未完成状态正确，等待保存并重载后选段恢复；修改人物声音来源后会正确重建缓存并更新来源状态。原项目文件内容哈希保持不变，测试中没有 API 请求或页面错误。

打包流程中的 TypeScript 类型检查、Vite 生产构建和 Windows x64 便携包生成均通过。构建仍提示已有分块循环引用及部分文件体积较大，本次未调整分块配置；未追加全量界面或功能回归。

## 使用与交付

版本从 2.9.2 升至 2.9.3，历史版本及交付文件保留。保存项目并退出旧版后打开新便携版，保留 EXE 旁完整的“莲华视频导演台数据”文件夹。
