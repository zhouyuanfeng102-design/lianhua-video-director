# RunningHub多ZIP输出接收验收（0.5.134）

## 根因

只读核对了用户指定失败任务的结果元信息：同一成功任务先返回调试ZIP，再返回真正的视频ZIP，后面还有文本输出。旧代码只选第一个ZIP；调试ZIP没有视频，后面的正常成片就被漏掉。用户提供的ZIP本身正常，解出的MP4具有H.264画面、AAC音轨，1056×704、15.083333秒。

未写入正式项目、未修改用户ZIP/MP4、未重新提交云端生成任务，也没有读取或输出密钥。

## 修复范围

- 枚举同一结果中的全部允许视频/ZIP候选，保持直接视频优先，地址去重。
- 当前候选下载或验证失败时继续下一候选；显式输出节点过滤仍严格生效，不按文件名猜测哪个节点正确。
- 每个候选分别决定认证头，避免跨域传递密钥。
- 赢家地址同时保存到任务、资产来源与断点；旧失败任务可使用原成功响应恢复。
- 取消、任务替换、项目删除或过期回调立即停止后续候选；已停止的链式后段不自动重启。
- ZIP路径、CRC、解压额度、FFprobe、原子发布等安全检查不放宽；空ZIP的提示明确只针对当前ZIP，而非整个云端任务。

## 验证

1. `scripts/videoArchiveSampleQa.mjs`：在Node与Electron Node模式，以用户样本只读运行生产下载、解包与FFprobe；显式ZIP提示、签名识别和直接MP4均成功，输出字节与手动解压文件完全相同。
2. `scripts/runningHubMultiOutputUiQa.mjs`：主代理使用Playwright Interactive，真实任务卡按钮与VideoGenerationEngine，经隔离桥接调用生产下载/解包代码、真实FFprobe、实际项目保存及checkpoint journal。首个ZIP为合成调试包，第二个为只读用户样本。
3. 实际点击“重新获取成片（不重新生成）”：下载顺序为1→2，只保存1个视频；0次任务查询、0次生成请求；任务/资产/journal/持久化文件均引用第二个输出，画面、声音和SHA-256与原文件一致。
4. 额外实际界面检查指定调试节点的情况：只请求该1个ZIP，不越界取其它节点，不产生资产，也不新增生成请求。
5. 任务保持静态缩略显示，没有挂载video播放器。1280×800及1120×720、100%/130%字体的成功卡片独立截图复核，无横向溢出或遮挡；生成快照展开/收起正常。
6. 单测覆盖同步成功、轮询成功、旧失败任务、当前允许地址优先、所有候选失败诊断、跨域认证、取消/移除/Abort/快照更换、以及ZIP安全边界。

截图和统计报告：`output/playwright/multi-output-134/`。测试媒体与状态仅写入经验证的临时目录，清理时再次验证输入文件哈希。用户原始样本保留，未复制进源码包或永久测试fixtures。

此前的本地语义拦截移除等改动保留。本次只修云端结果接收，不承诺改变云端生成质量或恢复已经在云端过期的文件。
